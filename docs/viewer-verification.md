# Offline viewer additions and verification

Implemented and verified on October 21, 2026. Fresh demonstration: [viewer.html](../work/viewer-verification/demo/viewer.html). The generated files under `work/` are intentionally ignored by Git. The demonstration contains synthetic CT voxels and illustrative masks, uses the production generator, and is visibly marked as synthetic. No retained patient result was available. Initial viewer verification used the synthetic phantom directly; the live-upload follow-up below also exercised real GPU inference on synthetic DICOM data.

The existing generator is `app/export/preview.py`, with `viewer_template.html` providing the Persian RTL viewer. Existing functionality included lossless packed integer CT slices (bounded quantization for fractional HU), aligned label PNGs, window/level, selection, opacity, contours, navigation/cine, ruler, zoom/pan, themes, snapshots and offline export. Volumes and original maximum-occupancy navigation already existed. Detailed geometry was available in the source DICOM volume but was missing from the HTML. Editing, detailed interactive measurements, anatomical multiplanar reconstruction and surface rendering were new.

| Addition | Implemented behavior |
| --- | --- |
| Measurements | Voxel-count volume in mL, patient RAS axis bounding dimensions including voxel boundaries, maximum native acquisition section area, corresponding section navigation, clickable area chart and accessible section slider, markers, local JSON download, explicit empty and boundary/partial states. |
| Paired structures | Left/right volumes and dimensions, absolute difference, signed percentage difference with explicitly displayed left reference, navigation, unavailable handling without NaN/Infinity, and no disease interpretation. Left/right tokens are matched throughout label names, including ribs. |
| Physician editing | Explicit current-native-display-slice mode; physical mm brush/eraser; protection of other labels; stroke undo/redo; immutable originals; original/edited display and original outline comparison; per-label review; approval invalidation after changes; protected reset to original. |
| Version packages | Separate downloadable/importable JSON, schema/version, source result and available study/series/frame identifiers, SHA-256 original-data fingerprint, shape, full geometry/voxel transform, label mapping, documented sparse changes, UTC creation time, available authenticated result-creator identity, review states and relationship to original. Imports validate the entire package before applying any change and require local review again. |
| Multiplanar views | Anatomical axial/coronal/sagittal reconstructions in RAS, synchronized physical crosshairs and sliders, aligned overlays and active-structure markers, and correct physical canvas aspect ratios. CT and labels use the same nearest-neighbor affine mapping. |
| Optional 3D | Lazy extraction of exact exposed voxel surfaces in physical coordinates, assigned colors, independent visibility/opacity, WebGL rotation/zoom/reset, exact voxel-ray picking of structures and physical points, synchronization with 2D, and mesh rebuild after edits. Buffers are invalidated immediately on relevant edits, and cancellation/hiding releases surfaces. |
| Performance and fallback | Worker measurements/resampling/extraction/picking; per-label measurement caches invalidated only for affected labels; slice-bounded PNG decoding into compact worker volumes; bounded undo history and mesh allocations; progress/cancellation; stale-request guards; collapsible panels; mobile layout; usable original CT viewer when optional capabilities are unavailable. |

Section areas explicitly refer to **native acquisition planes**, after applying the documented permutation/flips to the display grid; the acquisition section axis is preserved even if it becomes display x or y. They are not presented as patient-axial areas for oblique or sagittal acquisition. The three added anatomical views are reconstructed independently through the full affine. Volume and bounding measurements always use original-grid voxel geometry, never canvas size, zoom or display meshes. RAS bounding dimensions are right–left, anterior–posterior and inferior–superior extents, not anatomical length or RECIST diameter. Physical boundary extents include each voxel's half-width in every patient axis.

`viewer_geometry.py` accepts coded NIfTI geometry with known spatial units, or the existing DICOM pipeline's explicitly validated mm affine. Missing coded orientation/origin or unknown physical units disable measurements, mm editing, ruler, MPR and 3D with a Persian explanation. The normal local pipeline now additively passes its already available affine, study/series/frame identifiers and authenticated result creator to both viewer-generation calls. No inference, storage, database, authentication, API or deployment behavior was changed. The affine/voxel-center conventions follow [NiBabel coordinate systems](https://nipy.org/nibabel/coordinate_systems.html) and the [DICOM Image Plane Module](https://dicom.nema.org/medical/Dicom/2018c/output/chtml/part03/sect_C.7.6.2.html).

UI/UX redesign after usability feedback: the export now uses a fixed desktop workspace with the structure list on the right, a large central viewport and an inspector on the left. Top-level tabs switch between native 2D, synchronized MPR and 3D without navigating a long page. Search, quick paired-organ groups, selection chips and independent checkboxes control a single shared **multiple-region selection**. Measurements show separate cards for every selected region, the area chart plots all selected masks in their assigned colors, and measurement downloads include `selected_measurements`. Clicking a card changes the inspection focus while preserving other selections. The former `activeStructure` single selector was removed; `editTarget` is explicitly the destination of a 2D brush stroke and does not restrict the multi-selection. A single 3D action builds all selected regions, updates when the shared selection changes, and fits the camera around the selected surfaces. One-click brush access, separate measurement/editing tabs, compact contextual help and a mobile structure drawer reduce navigation. Native canvas sizing and MPR/3D layout preserve physical aspect ratios through desktop/mobile resizing. Original voxel data, geometry, inference and API contracts are unchanged. MPR/3D controls now become available only after measurement caches finish initializing, preventing a quick first click from silently producing an empty surface request. The retained synthetic live response was refreshed with the final UI script without changing its embedded payload; its browser report verifies 5 simultaneous selections, 5 measurement cards, 5 chart series and 5 rendered meshes with no page errors.

The redesigned workspace passed the 36 Python tests, 8 actual-worker tests, Firefox/Chromium offline regressions and the expanded Chromium workflow covering simultaneous measurement cards, multiple chart series, shared multi-selection, batch 3D construction, one-click brush and responsive navigation. After an idle-worker reload, an authenticated live upload of synthetic DICOM data returned the redesigned HTML in **14.09 seconds**, with HTTP 200, all 117 classes and 5 nonempty masks. Reproduce unit tests and fresh exports:

```bash
python3 -m unittest discover -s tools -p 'test_*.py' -v
node --test tools/test_viewer_worker.cjs
python3 -m tools.generate_viewer_demo
python3 -m tools.check_viewer_browser work/viewer-verification/demo/viewer.html --browser firefox --offline
python3 -m tools.check_viewer_browser work/viewer-verification/demo/viewer.html --browser chromium --offline
```

The advanced browser test uses a test-only Playwright installation under ignored `work/`; the generated viewer itself has no added runtime dependencies. Node 18 can use Playwright 1.50.1. Set `CHROMIUM_PATH` to an unsandboxed-install Chromium binary if the system browser's Snap filesystem isolation prevents Playwright from retrieving downloaded files:

```bash
npm install --prefix work/viewer-verification --no-audit --no-fund playwright@1.50.1
PLAYWRIGHT_BROWSERS_PATH="$PWD/work/viewer-verification/browsers" node work/viewer-verification/node_modules/playwright/cli.js install chromium
node tools/check_viewer_advanced.cjs
```

Limits are explicit in the viewer: edits remain local and require downloading a package before closing the file; no server save endpoint was added. Available authenticated identity is the result creator captured during generation, not an authenticated offline physician signature; unavailable identity is null. Package review states do not establish reviewer authentication, and imported masks need review again. Unknown geometry disables the affected capabilities. MPR display grids are capped at 768 pixels per axis, while measurements and edits remain on the native grid. Surfaces are intentionally unsmoothed voxel boundaries, with a maximum of 2.4 million vertices per extraction request; select fewer structures if the limit is reached. Undo history has an estimated 32 MiB bound. Reset preserves another label's explicit additions if restoring the selected original would overwrite them. These are viewer engineering checks on synthetic data, not validation of segmentation accuracy on clinical cases.
